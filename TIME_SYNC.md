# Установка даты и времени с телефона

[Описание устройства и оглавление](README.md) · [Сборка и заливка прошивки](INSTALL.md)

Телефон записывает дату и время в ESP32 через Bluetooth Low Energy (BLE),
а ESP32 сохраняет их в RTC PCF8563. Перепрошивать устройство для этого не нужно.

<a id="requirements"></a>
## Что понадобится

- Включённое устройство с [прошивкой проекта](INSTALL.md), подключёнными RTC и OLED.
- Телефон Android или iPhone с Bluetooth.
- Приложение **nRF Connect for Mobile** от Nordic Semiconductor. Оно позволяет
  находить BLE-устройства и записывать характеристики. Сведения о приложении:
  [официальная страница Nordic](https://www.nordicsemi.com/Products/Development-tools/nRF-Connect-for-mobile),
  [Android](https://github.com/nordicsemi/Android-nRF-Connect),
  [iOS](https://github.com/nordicsemi/IOS-nRF-Connect).

ELM327 и подключение телефона к его Wi-Fi для установки времени не требуются.
Текущее время вводится вручную: готового приложения, которое автоматически
берёт время телефона и отправляет его в устройство, в проекте нет.

<a id="connection"></a>
## Параметры подключения

| Параметр | Значение |
|---|---|
| Имя BLE-устройства | `NexiaBLE` |
| UUID сервиса | `12345678-1234-1234-1234-1234567890ab` |
| UUID характеристики времени | `abcdefab-1234-5678-1234-abcdefabcdef` |
| Операция | `Write Request` / запись с ответом |
| Представление данных | Текст UTF-8 / ASCII |
| Размер значения | Ровно 19 байт |
| Формат | `YYYY-MM-DD HH:MM:SS` |

Характеристика поддерживает запись с ответом. Режим **Write Without Response**
не объявлен; чтения и уведомлений с текущим временем тоже нет.

<a id="write-time"></a>
## Как записать время с Android или iPhone

Названия и значки элементов nRF Connect могут отличаться между версиями и ОС;
выбирайте операции сканирования, подключения и записи характеристики.

1. Включите ESP32 и дождитесь появления часов. Для удобства оставьте экран часов.
2. Включите Bluetooth на телефоне, откройте **nRF Connect for Mobile** и
   предоставьте запрошенное системой разрешение на доступ к Bluetooth /
   поиск устройств. На Android разрешите доступ к местоположению, если его
   запрашивает система для BLE-сканирования.
3. Запустите сканирование (**Scan**) и найдите **NexiaBLE**. Подключитесь к нему
   из приложения (**Connect**); отдельное сопряжение в настройках Bluetooth
   для текущей прошивки не требуется.
4. Откройте сервис с UUID `12345678-1234-1234-1234-1234567890ab`.
   Приложение может показывать его как неизвестный сервис (**Unknown Service**).
5. Внутри найдите характеристику `abcdefab-1234-5678-1234-abcdefabcdef`.
   Выберите действие записи (**Write**).
6. В окне записи выберите текстовое представление **Text / UTF-8 / ASCII**
   и тип операции **Write Request** (с ответом). Введите актуальные дату и время,
   например:

   ```text
   2026-10-18 14:30:00
   ```

   Это только пример формата — замените значение текущим временем.
   Отправляйте одну строку без кавычек, перевода строки и пробелов по краям.
7. Отправьте значение. Проверьте дату и часы на OLED по
   [описанию результата](#verify).
8. Отключитесь от устройства в приложении. Для следующей установки времени
   подключитесь снова и повторите запись.

Если приложение открывает ввод в HEX, переключите представление на текст.
Не вводите строку даты в поле шестнадцатеричных байтов.

<a id="format"></a>
## Формат и часовой пояс

```text
YYYY-MM-DD HH:MM:SS
2026-10-18 14:30:00
```

| Часть | Допустимое значение |
|---|---|
| `YYYY` | Год `2000`–`2099`, четыре цифры |
| `MM` | Месяц `01`–`12` |
| `DD` | Существующий день указанного месяца и года |
| `HH` | Часы `00`–`23` |
| `MM` после часов | Минуты `00`–`59` |
| `SS` | Секунды `00`–`59` |

Между датой и временем — один обычный пробел, между частями даты — дефисы,
между часами, минутами и секундами — двоеточия. Все числа записываются цифрами
ASCII, с ведущими нулями.

Передавайте **местное время, которое хотите видеть на дисплее**. Например,
для Москвы вводите московское время. Прошивка не конвертирует UTC, не принимает
смещение `+03:00` или суффикс `Z` и не меняет часовой пояс автоматически.
При переезде в другой пояс или переводе часов отправьте новое местное время.

Неверные примеры:

| Значение | Причина |
|---|---|
| `18.10.2026 14:30:00` | Неверный порядок и разделители даты |
| `2026-10-18T14:30:00` | Вместо пробела стоит `T` |
| `2026-10-18 4:30:00` | Часы без ведущего нуля |
| `2026-02-29 14:30:00` | В 2026 году нет 29 февраля |
| `2026-10-18 24:00:00` | Часы должны быть от 00 до 23 |

Прошивка проверяет формат, диапазоны и календарную дату перед записью в RTC.

<a id="verify"></a>
## Как проверить результат

- На экране часов должны появиться переданные часы и минуты, а также дата
  в формате `DD.MM.YY`. Для примера выше это `14:30` и `18.10.26`.
- Секунды сохраняются в RTC, хотя на OLED не выводятся.
- Если открыт экран OBD, нажмите кнопку, чтобы перейти к часам.
- Подтверждение BLE-записи означает доставку значения, но не подтверждает
  прохождение календарной проверки: отдельного ответа об установке времени
  прошивка не отправляет. Окончательно проверяйте результат на дисплее.
- При исправном резервном питании RTC время должно сохраняться после
  отключения основного питания. Если RTC сообщает потерю питания, прошивка
  устанавливает время компиляции — после этого задайте точное время снова.

<a id="troubleshooting"></a>
## Решение проблем

| Проблема | Что сделать |
|---|---|
| `NexiaBLE` не найден | Проверить питание и запуск часов, приблизить телефон, разрешения Bluetooth и повторить сканирование |
| После заставки часы не появились | Проверить подключение RTC по [инструкции сборки и заливки](INSTALL.md#troubleshooting) |
| Характеристика не найдена | Проверить оба UUID и что установлена прошивка этого проекта; переподключиться и обновить список сервисов |
| Ошибка записи | Выбрать `Write Request`, текстовое представление и строку ровно из 19 байт |
| Запись прошла, время не изменилось | Проверить дату, диапазоны, ведущие нули, отсутствие лишних символов; открыть экран часов |
| Время отличается на несколько часов | Передать местное время: автоматического преобразования часового пояса нет |
| Время сбрасывается после отключения питания | Проверить резервное питание RTC; затем повторить запись |
| Повторное подключение не удаётся | Завершить прежнее соединение в приложении и повторить сканирование; при необходимости перезапустить ESP32 |

Эти действия соответствуют текущему обработчику прошивки. Проверка с реальным
Android/iPhone и платой пока не выполнена.
