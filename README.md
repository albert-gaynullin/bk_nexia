<a id="purpose"></a>
## 1. Назначение

Устройство на базе ESP32 предназначено для установки в автомобиле и выполняет следующие функции:

- получение параметров автомобиля через Wi-Fi ELM327;
- отображение параметров на OLED SSD1306 128×64;
- отображение текущих даты и времени;
- хранение времени во внешнем RTC PCF8563;
- установка местного времени телефона / ПК через браузер;
- обновление прошивки по Wi-Fi через браузер (OTA);
- переключение экранов кнопкой.

Отображаемые параметры автомобиля:

- напряжение бортовой сети;
- уровень топлива;
- температура охлаждающей жидкости.

<a id="architecture"></a>
## 3. Общая архитектура

```text
Обычный режим:
Кнопка ── GPIO13 ── ESP32 ── I²C ── OLED + RTC PCF8563
                     │
                     └── Wi-Fi (STA) ── ELM327 ── OBD-II автомобиля

Режим настройки (кнопка при запуске):
Телефон / ПК ── Wi-Fi (AP) ── ESP32 ── I²C ── RTC + OLED
                                 │
                                 └── браузер: время + OTA-образ
```

Режимы Wi-Fi разделены: в обычном режиме ESP32 подключается к ELM327,
а в режиме настройки создаёт свою сеть. OBD-опрос в режиме настройки не запускается.
Bluetooth в текущей прошивке не используется.

<a id="esp32"></a>
## 4. Подключение ESP32

Для стандартной ESP32 DevKit используются следующие GPIO:

| Функция | GPIO |
|---|---:|
| I²C SDA | GPIO21 |
| I²C SCL | GPIO22 |
| Кнопка | GPIO13 |

Шина I²C используется одновременно OLED и RTC.

<a id="oled"></a>
## 5. Подключение OLED SSD1306

Используется дисплей:

- SSD1306;
- разрешение 128×64;
- интерфейс I²C;
- адрес `0x3C`.

В коде:

```cpp
Adafruit_SSD1306 display(128, 64, &Wire, -1);
```

Инициализация:

```cpp
display.begin(SSD1306_SWITCHCAPVCC, 0x3C);
```

### Распиновка

| OLED SSD1306 | ESP32 |
|---|---|
| VCC | 3.3V |
| GND | GND |
| SDA | GPIO21 |
| SCL | GPIO22 |

Схема:

```text
OLED SSD1306          ESP32
┌──────────┐
│ VCC ──────────────── 3.3V
│ GND ──────────────── GND
│ SDA ──────────────── GPIO21
│ SCL ──────────────── GPIO22
└──────────┘
```

<a id="rtc"></a>
## 6. Подключение RTC PCF8563

Используется RTC:

```cpp
RTC_PCF8563 rtc;
```

PCF8563 работает по I²C и подключается к той же шине, что и OLED.

Типичный I²C-адрес PCF8563:

```text
0x51
```

### Распиновка

| RTC PCF8563 | ESP32 |
|---|---|
| VCC | 3.3V |
| GND | GND |
| SDA | GPIO21 |
| SCL | GPIO22 |

Схема:

```text
PCF8563               ESP32
┌──────────┐
│ VCC ──────────────── 3.3V
│ GND ──────────────── GND
│ SDA ──────────────── GPIO21
│ SCL ──────────────── GPIO22
└──────────┘
```

### Общая I²C-шина

OLED и PCF8563 подключаются параллельно:

```text
                         ESP32
                    ┌─────────────┐
                    │             │
GPIO21 SDA ─────────┼──────┬──────┼──── OLED SDA
                    │      │      │
                    │      └────────── PCF8563 SDA
                    │             │
GPIO22 SCL ─────────┼──────┬──────┼──── OLED SCL
                    │      │      │
                    │      └────────── PCF8563 SCL
                    │             │
3.3V ───────────────┼──────┬──────┼──── OLED VCC
                    │      └────────── PCF8563 VCC
                    │             │
GND ────────────────┼──────┬──────┼──── OLED GND
                    │      └────────── PCF8563 GND
                    └─────────────┘
```

Разные I²C-адреса позволяют устройствам одновременно работать на одной шине:

```text
SSD1306  → 0x3C
PCF8563  → 0x51
```

<a id="button"></a>
## 7. Подключение кнопки

Кнопка подключена к GPIO13:

```cpp
#define pushButton_pin 13
```

В `setup()` используется:

```cpp
pinMode(pushButton_pin, INPUT_PULLUP);
```

Поэтому внешний подтягивающий резистор не требуется.

### Подключение

```text
ESP32

GPIO13 ────────────────┐
                       │
                    [ КНОПКА ]
                       │
GND ───────────────────┘
```

Логика:

| Состояние | GPIO13 |
|---|---|
| Кнопка отпущена | HIGH |
| Кнопка нажата | LOW |

В актуальной прошивке строка `attachInterrupt` не используется: кнопка
опрашивается в `loop()` функцией `changeMod()`. Изменение уровня должно быть
стабильным 40 мс; режим переключается один раз при нажатии.

Удержание этой же кнопки при включении около 3 секунд запускает
[режим настройки и OTA](OTA.md#upload). Кнопка BOOT на плате используется
только для USB-загрузчика и не заменяет кнопку GPIO13.

<a id="elm327"></a>
## 8. Wi-Fi ELM327

ELM327 не соединяется с ESP32 проводом.

Адаптер подключается непосредственно к диагностическому разъёму OBD-II автомобиля.

```text
ESP32
  │
  │ Wi-Fi
  ▼
Wi-Fi ELM327
  │
  │ OBD-II
  ▼
Автомобиль / ECU
```

### Параметры подключения

В программе указано:

```cpp
const char* ssid = "WiFi_OBDII";
```

ESP32 должна подключаться к Wi-Fi сети:

```text
SSID: WiFi_OBDII
```

IP-адрес сервера:

```cpp
IPAddress server(192, 168, 0, 10);
```

TCP-порт:

```cpp
35000
```

Итог:

```text
ELM327 IP:   192.168.0.10
TCP port:    35000
```

Подключение выполняется:

```cpp
client.connect(server, 35000);
```

<a id="obd-parameters"></a>
## 9. OBD-II параметры

Устройство получает три параметра.

### 9.1. Температура охлаждающей жидкости

Используется:

```cpp
myELM327->engineCoolantTemp();
```

Полученное значение записывается в:

```cpp
e_temp
```

На дисплее выводится температура в °C.

---

### 9.2. Напряжение

Используется:

```cpp
myELM327->batteryVoltage();
```

Полученное значение записывается в:

```cpp
b_volt
```

На дисплее выводится:

```text
12.4V
```

---

### 9.3. Уровень топлива

Используется:

```cpp
myELM327->processPID(34, 4805, 1, 1);
```

Результат преобразуется:

```cpp
f_lvl_tmp = (fuel_level / 255.0) * 50.0;
```

Таким образом, программа предполагает объём бака:

```text
50 литров
```

После этого выполняется сглаживание показаний по 10 последним значениям.

---

<a id="fuel-smoothing"></a>
## 10. Сглаживание уровня топлива

Используется массив:

```cpp
float fuel_array[10];
```

Каждое новое значение добавляется в массив.

После этого рассчитывается среднее:

```cpp
f_lvl = array_sum / 10;
```

Это уменьшает скачки показаний уровня топлива.

Принцип:

```text
OBD значение
     │
     ▼
┌───────────────┐
│ 10 последних  │
│   значений    │
└───────┬───────┘
        │
        ▼
     Среднее
        │
        ▼
   OLED дисплей
```

<a id="rtc-init"></a>
## 12. Инициализация RTC

При запуске `init_rtc()` проверяет доступность PCF8563 и возвращает `bool`.
Если RTC сообщает потерю питания, устанавливаются дата и время компиляции:

```cpp
if (rtc.lostPower()) {
    rtc.adjust(DateTime(F(__DATE__), F(__TIME__)));
    rtc.start();
}
```

Точное время затем задаётся [через браузер](TIME_SYNC.md). Если RTC недоступен,
экран часов показывает `RTC unavailable`; OBD и режим веб-обновления остаются
доступны. Запись времени через браузер в этом случае возвращает ошибку.

<a id="web-time"></a>
## 13. Веб-настройка времени

Для входа удерживайте кнопку GPIO13 при включении / перезапуске примерно
3 секунды, до экрана **NEXIA SETUP / OTA**, затем отпустите.

ESP32 создаёт сеть `Nexia-Setup-XXXX`, показывает на OLED случайный пароль
и адрес `http://192.168.4.1`. Подключитесь с телефона или ПК и откройте адрес
в браузере: имя пользователя `admin`, пароль тот же, что у Wi-Fi.

Кнопка **Установить время телефона / ПК** передаёт местное время браузера в RTC.
Прошивка проверяет дату, записывает её и считывает RTC обратно для подтверждения.
На этой же странице доступна загрузка прошивки по воздуху.

Пошаговые инструкции: [TIME_SYNC.md](TIME_SYNC.md) и [OTA.md](OTA.md).
После 10 минут бездействия устройство перезапускается в обычный режим.
Кнопка **Вернуться к часам** завершает настройку сразу.

<a id="time-format"></a>
## 14. Формат времени и веб-запросы

Формат местного времени: `YYYY-MM-DD HH:MM:SS`, например
`2026-10-18 14:30:00`. Браузер формирует строку автоматически. Допустимы
существующие календарные даты 2000–2099, часы 00–23, минуты и секунды 00–59.
Часовой пояс в RTC не хранится, автоматического преобразования UTC нет.

| Запрос | Назначение |
|---|---|
| `GET /` | Страница настройки и OTA |
| `GET /time` | Прочитать время RTC |
| `POST /time` | Установить время: поле формы `time` |
| `POST /update?size=N` | Передать один файл приложения в multipart-поле `firmware` |
| `POST /restart` | Перезапустить устройство в обычный режим |

Запросы требуют HTTP-авторизации `admin` с паролем текущей сети настройки.
Для изменяющих POST-запросов проверяется Origin страницы `http://192.168.4.1`.
Веб-страница передаёт его автоматически; внешний запрос без него будет отклонён.

Подтверждение установки времени возвращается только после чтения RTC обратно.
Формат и календарь проверяет [LocalTime.h](bk/LocalTime.h), обработчики находятся
в [DevicePortal.cpp](bk/DevicePortal.cpp).

<a id="modes"></a>
## 15. Режимы работы

Переключение выполняется кнопкой.

Переменная:

```cpp
int mode = 0;
```

Количество режимов:

```cpp
int mods_count = 2;
```

### Режим 0 — часы

```cpp
mode == 0
```

На дисплее отображаются:

- часы;
- минуты;
- дата.

Обновление выполняется раз в секунду.

Дата выводится в формате `DD.MM.YY`; запись в буфер ограничена `snprintf`.

---

### Режим 1 — параметры автомобиля

```cpp
mode == 1
```

На дисплее отображаются:

- напряжение;
- уровень топлива;
- температура охлаждающей жидкости.

Получение параметров выполняется последовательно.

OLED обновляется не чаще четырёх раз в секунду (кроме немедленного обновления
при переключении режима или изменении состояния связи). При отсутствии
достоверного показания выводится `--`.

<a id="obd-state"></a>
## 16. State machine OBD

Параметры опрашиваются по очереди:

```text
COOLANT_TEMP
      │
      ▼
   VOLTAG
      │
      ▼
     FUEL
      │
      ▼
COOLANT_TEMP
```

Соответствующее перечисление:

```cpp
typedef enum {
    COOLANT_TEMP,
    VOLTAG,
    FUEL
} obd_pid_states;
```

Это позволяет последовательно выполнять запросы к ELM327.

### Соединение и восстановление после ошибок

- Подключение начинается при первом открытии экрана OBD. Далее опрос и
  восстановление связи продолжаются и на экране часов.
- ESP32 работает в режиме `WIFI_STA`. Ожидание Wi-Fi ограничено 10 секундами,
  отдельная TCP-попытка — одной секундой.
- TCP-подключение и блокирующая инициализация ELMduino выполняются в отдельной
  задаче FreeRTOS. Её результат передаётся основному циклу через очередь.
  Каждый запрос инициализации имеет таймаут 2 секунды; вся последовательность
  может занять несколько таких интервалов. Во время ожидания сетевых данных
  задача уступает процессор, чтобы не блокировать idle task и watchdog.
- Готовность устанавливается только после успешного `begin()`. При новой
  попытке объект ELM327 пересоздаётся с освобождением прежнего буфера библиотеки.
- При потере Wi-Fi/TCP либо отсутствии любых успешных показаний 15 секунд
  соединение сбрасывается. Повторная попытка начинается через 5 секунд.
- Часы и кнопка продолжают обслуживаться во время подключения.
- Протокол `'5'`, адрес адаптера и пользовательский PID топлива сохранены.

В режиме настройки `DevicePortal` обслуживает время и OTA; задача ELM327
и её очередь в этом режиме не создаются.

<a id="wiring"></a>
## 17. Полная схема подключения

```text
ESP32 GPIO21 (SDA) ──┬── OLED SDA
                    └── PCF8563 SDA
ESP32 GPIO22 (SCL) ──┬── OLED SCL
                    └── PCF8563 SCL
ESP32 3.3V ──────────┬── OLED VCC
                    └── PCF8563 VCC
ESP32 GND ───────────┬── OLED GND
                    ├── PCF8563 GND
                    └── кнопка ── ESP32 GPIO13

Обычный режим:    ESP32 ── Wi-Fi ── ELM327 ── OBD-II автомобиля
Настройка / OTA:  телефон / ПК ── Wi-Fi ── точка доступа ESP32
```

Подробности питания — в [разделе 21](#power). Параметры точки доступа
отображаются на OLED только в режиме настройки.

<a id="startup"></a>
## 20. Порядок запуска

1. Serial 115200, кнопка GPIO13 и OLED; заставка `NEXIA`.
2. Проверка удержания кнопки при запуске примерно 3 секунды.
3. Инициализация RTC; при потере питания — установка времени компиляции.
4. Если кнопка удерживается: отдельная Wi-Fi-сеть и веб-интерфейс. OBD не запускается.
5. Без удержания: экран часов; короткое нажатие переключает часы / OBD.
6. После первого открытия экрана OBD запускаются подключение к ELM327 и опрос.

Веб-сервер и буферы OTA создаются только в режиме настройки. Ошибка RTC
не блокирует OTA: можно обновить прошивку и затем проверить подключение часов.

<a id="power"></a>
## 21. Питание

ESP32, OLED и PCF8563 должны получать подходящее низковольтное питание.

При установке устройства непосредственно в автомобиле **12 В бортовой сети нельзя подавать непосредственно на 3.3V-пины ESP32, OLED или RTC**.

Рекомендуемая архитектура питания:

```text
Автомобиль
    │
    │ 12 В
    ▼
DC/DC преобразователь
    │
    ├── 5 В → ESP32 VIN/5V*
                │
                └── 3.3 В → OLED + PCF8563
```

Конкретная схема зависит от используемой платы ESP32.

При автомобильной установке желательно учитывать:

- переполюсовку;
- скачки напряжения;
- импульсные выбросы бортовой сети;
- ток потребления ESP32;
- ток потребления OLED;
- резервное питание RTC;
- потребление ELM327 от OBD-II.

<a id="memory"></a>
## 23. Память и параметры сборки

Для ESP32 Dev Module с flash 4 МБ подходит стандартная таблица разделов
с двумя OTA-слотами по **1 310 720 байт**. Схема `Minimal SPIFFS` с OTA также
поддерживается. `Huge APP / No OTA` не подходит для обновления по воздуху.

Сравнение на ESP32 core 3.3.5 с одинаковыми библиотеками OBD / RTC / OLED:

| Версия | Flash приложения | Статическая RAM |
|---|---:|---:|
| Прежняя версия с Bluedroid | 1 688 227 Б | 62 324 Б |
| Прежняя версия с NimBLE | 1 207 823 Б | 56 992 Б |
| Время через браузер + веб-OTA | 1 018 827 Б | 47 320 Б |

Статическая RAM из отчёта компоновщика не включает динамические буферы Wi-Fi,
OLED, веб-сервера, записи flash и стеки создаваемых задач. Свободный и минимальный
heap на устройстве не измерены. Стек задачи ELM327 не уменьшался без аппаратных
измерений. Тесты логики — в [tests/README.md](tests/README.md).

Размер файла обновления должен помещаться в свободный OTA-слот установленной
таблицы разделов. Первая веб-версия заливается по USB; далее выбирайте файл
приложения `bk.ino.bin` по [OTA.md](OTA.md).

<a id="ota"></a>
## 25. Обновление по воздуху

Удерживайте кнопку GPIO13 при включении до экрана настройки, подключитесь
к сети и откройте адрес с OLED. На странице выберите `bk.ino.bin` и загрузите
его в блоке обновления. Дождитесь проверки образа и автоматического перезапуска.

Первую прошивку с этой функцией установите по USB. Для OTA нужны два раздела
приложения; таблица разделов по воздуху не меняется. Подробности и порядок
аппаратной проверки — в [OTA.md](OTA.md).
