<a id="purpose"></a>
## 1. Назначение

Устройство на базе ESP32 предназначено для установки в автомобиле и выполняет следующие функции:

- получение параметров автомобиля через Wi-Fi ELM327;
- отображение параметров на OLED SSD1306 128×64;
- отображение текущих даты и времени;
- хранение времени во внешнем RTC PCF8563;
- синхронизация времени с телефона через Bluetooth Low Energy (BLE);
- переключение экранов кнопкой.

Отображаемые параметры автомобиля:

- напряжение бортовой сети;
- уровень топлива;
- температура охлаждающей жидкости.

<a id="esp32"></a>
## 4. Подключение ESP32

Для стандартной ESP32 DevKit используются следующие GPIO:

| Функция | GPIO |
|---|---:|
| I²C SDA | GPIO21 |
| I²C SCL | GPIO22 |
| Кнопка | GPIO13 |

Шина I²C используется одновременно OLED и RTC.

---

<a id="oled"></a>
## 5. Подключение OLED SSD1306

Используется дисплей:

- SSD1306;
- разрешение 128×64;
- интерфейс I²C;
- адрес `0x3C`.

В коде:

```cpp
Adafruit_SSD1306 display(128, 64, &Wire, -1);
```

Инициализация:

```cpp
display.begin(SSD1306_SWITCHCAPVCC, 0x3C);
```

### Распиновка

| OLED SSD1306 | ESP32 |
|---|---|
| VCC | 3.3V |
| GND | GND |
| SDA | GPIO21 |
| SCL | GPIO22 |

Схема:

```text
OLED SSD1306          ESP32
┌──────────┐
│ VCC ──────────────── 3.3V
│ GND ──────────────── GND
│ SDA ──────────────── GPIO21
│ SCL ──────────────── GPIO22
└──────────┘
```

<a id="rtc"></a>
## 6. Подключение RTC PCF8563

Используется RTC:

```cpp
RTC_PCF8563 rtc;
```

PCF8563 работает по I²C и подключается к той же шине, что и OLED.

Типичный I²C-адрес PCF8563:

```text
0x51
```

### Распиновка

| RTC PCF8563 | ESP32 |
|---|---|
| VCC | 3.3V |
| GND | GND |
| SDA | GPIO21 |
| SCL | GPIO22 |

Схема:

```text
PCF8563               ESP32
┌──────────┐
│ VCC ──────────────── 3.3V
│ GND ──────────────── GND
│ SDA ──────────────── GPIO21
│ SCL ──────────────── GPIO22
└──────────┘
```

### Общая I²C-шина

OLED и PCF8563 подключаются параллельно:

```text
                         ESP32
                    ┌─────────────┐
                    │             │
GPIO21 SDA ─────────┼──────┬──────┼──── OLED SDA
                    │      │      │
                    │      └────────── PCF8563 SDA
                    │             │
GPIO22 SCL ─────────┼──────┬──────┼──── OLED SCL
                    │      │      │
                    │      └────────── PCF8563 SCL
                    │             │
3.3V ───────────────┼──────┬──────┼──── OLED VCC
                    │      └────────── PCF8563 VCC
                    │             │
GND ────────────────┼──────┬──────┼──── OLED GND
                    │      └────────── PCF8563 GND
                    └─────────────┘
```

Разные I²C-адреса позволяют устройствам одновременно работать на одной шине:

```text
SSD1306  → 0x3C
PCF8563  → 0x51
```

<a id="button"></a>
## 7. Подключение кнопки

Кнопка подключена к GPIO13:

```cpp
#define pushButton_pin 13
```

В `setup()` используется:

```cpp
pinMode(pushButton_pin, INPUT_PULLUP);
```

Поэтому внешний подтягивающий резистор не требуется.

### Подключение

```text
ESP32

GPIO13 ────────────────┐
                       │
                    [ КНОПКА ]
                       │
GND ───────────────────┘
```

Логика:

| Состояние | GPIO13 |
|---|---|
| Кнопка отпущена | HIGH |
| Кнопка нажата | LOW |

В актуальной прошивке строка `attachInterrupt` не используется: кнопка
опрашивается в `loop()` функцией `changeMod()`. Изменение уровня должно быть
стабильным 40 мс; режим переключается один раз при нажатии.

<a id="elm327"></a>
## 8. Wi-Fi ELM327

ELM327 не соединяется с ESP32 проводом.

Адаптер подключается непосредственно к диагностическому разъёму OBD-II автомобиля.

```text
ESP32
  │
  │ Wi-Fi
  ▼
Wi-Fi ELM327
  │
  │ OBD-II
  ▼
Автомобиль / ECU
```

### Параметры подключения

В программе указано:

```cpp
const char* ssid = "WiFi_OBDII";
```

ESP32 должна подключаться к Wi-Fi сети:

```text
SSID: WiFi_OBDII
```

IP-адрес сервера:

```cpp
IPAddress server(192, 168, 0, 10);
```

TCP-порт:

```cpp
35000
```

Итог:

```text
ELM327 IP:   192.168.0.10
TCP port:    35000
```

Подключение выполняется:

```cpp
client.connect(server, 35000);
```

<a id="obd-parameters"></a>
## 9. OBD-II параметры

Устройство получает три параметра.

### 9.1. Температура охлаждающей жидкости

Используется:

```cpp
myELM327->engineCoolantTemp();
```

Полученное значение записывается в:

```cpp
e_temp
```

На дисплее выводится температура в °C.

---

### 9.2. Напряжение

Используется:

```cpp
myELM327->batteryVoltage();
```

Полученное значение записывается в:

```cpp
b_volt
```

На дисплее выводится:

```text
12.4V
```

---

### 9.3. Уровень топлива

Используется:

```cpp
myELM327->processPID(34, 4805, 1, 1);
```

Результат преобразуется:

```cpp
f_lvl_tmp = (fuel_level / 255.0) * 50.0;
```

Таким образом, программа предполагает объём бака:

```text
50 литров
```

После этого выполняется сглаживание показаний по 10 последним значениям.

---

<a id="fuel-smoothing"></a>
## 10. Сглаживание уровня топлива

Используется массив:

```cpp
float fuel_array[10];
```

Каждое новое значение добавляется в массив.

После этого рассчитывается среднее:

```cpp
f_lvl = array_sum / 10;
```

Это уменьшает скачки показаний уровня топлива.

Принцип:

```text
OBD значение
     │
     ▼
┌───────────────┐
│ 10 последних  │
│   значений    │
└───────┬───────┘
        │
        ▼
     Среднее
        │
        ▼
   OLED дисплей
```

<a id="clock"></a>
## 11. RTC и отображение времени

Текущее время считывается:

```cpp
DateTime now = rtc.now();
```

Время:

```cpp
now.hour()
now.minute()
```

Дата:

```cpp
now.day()
now.month()
now.year()
```

На дисплее отображается:

```text
22:15
21.08.26
```

<a id="rtc-init"></a>
## 12. Инициализация RTC

При запуске:

```cpp
init_rtc();
```

Проверяется наличие RTC:

```cpp
if (!rtc.begin()) {
    ...
}
```

Если RTC потерял питание:

```cpp
if (rtc.lostPower()) {
    rtc.adjust(DateTime(F(__DATE__), F(__TIME__)));
    rtc.start();
}
```

В этом случае RTC устанавливается на дату и время компиляции прошивки.

<a id="ble-time"></a>
## 13. BLE-синхронизация времени

ESP32 создаёт BLE-устройство:

```cpp
NimBLEDevice::init("NexiaBLE");
```

Имя устройства:

```text
NexiaBLE
```

Используются:

```text
Service UUID:
12345678-1234-1234-1234-1234567890ab

Characteristic UUID:
abcdefab-1234-5678-1234-abcdefabcdef
```

Характеристика имеет разрешение:

```cpp
NIMBLE_PROPERTY::WRITE
```

То есть телефон может записать в неё строку с датой и временем.
Пошаговая настройка через nRF Connect — в
[инструкции для телефона](TIME_SYNC.md#write-time).

<a id="ble-format"></a>
## 14. Формат времени BLE

Ожидаемый формат:

```text
YYYY-MM-DD HH:MM:SS
```

Пример:

```text
2025-08-21 22:15:00
```

Полученное значение разбирается:

```cpp
sscanf(
    message.value,
    "%4d-%2d-%2d %2d:%2d:%2d",
    &year,
    &month,
    &day,
    &hour,
    &minute,
    &second
);
```

После успешного разбора:

```cpp
rtc.adjust(
    DateTime(
        year,
        month,
        day,
        hour,
        minute,
        second
    )
);
```

Таким образом:

```text
Смартфон
   │
   │ BLE
   ▼
ESP32
   │
   │ I²C
   ▼
PCF8563
```

<a id="modes"></a>
## 15. Режимы работы

Переключение выполняется кнопкой.

Переменная:

```cpp
int mode = 0;
```

Количество режимов:

```cpp
int mods_count = 2;
```

### Режим 0 — часы

```cpp
mode == 0
```

На дисплее отображаются:

- часы;
- минуты;
- дата.

Обновление выполняется раз в секунду.

Дата выводится в формате `DD.MM.YY`; запись в буфер ограничена `snprintf`.

---

### Режим 1 — параметры автомобиля

```cpp
mode == 1
```

На дисплее отображаются:

- напряжение;
- уровень топлива;
- температура охлаждающей жидкости.

Получение параметров выполняется последовательно.

OLED обновляется не чаще четырёх раз в секунду (кроме немедленного обновления
при переключении режима или изменении состояния связи). При отсутствии
достоверного показания выводится `--`.

<a id="obd-state"></a>
## 16. State machine OBD

Параметры опрашиваются по очереди:

```text
COOLANT_TEMP
      │
      ▼
   VOLTAG
      │
      ▼
     FUEL
      │
      ▼
COOLANT_TEMP
```

Соответствующее перечисление:

```cpp
typedef enum {
    COOLANT_TEMP,
    VOLTAG,
    FUEL
} obd_pid_states;
```

Это позволяет последовательно выполнять запросы к ELM327.

### Соединение и восстановление после ошибок

- Подключение начинается при первом открытии экрана OBD. Далее опрос и
  восстановление связи продолжаются и на экране часов.
- ESP32 работает в режиме `WIFI_STA`. Ожидание Wi-Fi ограничено 10 секундами,
  отдельная TCP-попытка — одной секундой.
- TCP-подключение и блокирующая инициализация ELMduino выполняются в отдельной
  задаче FreeRTOS. Её результат передаётся основному циклу через очередь.
  Каждый запрос инициализации имеет таймаут 2 секунды; вся последовательность
  может занять несколько таких интервалов. Во время ожидания сетевых данных
  задача уступает процессор, чтобы не блокировать idle task и watchdog.
- Готовность устанавливается только после успешного `begin()`. При новой
  попытке объект ELM327 пересоздаётся с освобождением прежнего буфера библиотеки.
- При потере Wi-Fi/TCP либо отсутствии любых успешных показаний 15 секунд
  соединение сбрасывается. Повторная попытка начинается через 5 секунд.
- Часы, кнопка и BLE продолжают обслуживаться во время подключения.
- Протокол `'5'`, адрес адаптера и пользовательский PID топлива сохранены.

Запись времени BLE передаётся через очередь длиной в одно сообщение: если
пришло несколько значений до обработки, используется последнее. Принимается
строка длиной 19 символов `YYYY-MM-DD HH:MM:SS`; перед изменением RTC
проверяются диапазоны, календарная дата и год 2000–2099.

## 20. Порядок запуска

При включении ESP32:

```text
1. Запуск Serial
        ↓
2. Инициализация OLED
        ↓
3. Инициализация PCF8563
        ↓
4. Проверка потери питания RTC
        ↓
5. Запуск BLE NexiaBLE
        ↓
6. Запуск BLE-сервиса
        ↓
7. Запуск BLE-рекламы
        ↓
8. Режим часов
```

По нажатию кнопки:

```text
Режим часов
     │
     │ кнопка
     ▼
Режим OBD
     │
     │ кнопка
     ▼
Режим часов
```

<a id="power"></a>
## 21. Питание

ESP32, OLED и PCF8563 должны получать подходящее низковольтное питание.

При установке устройства непосредственно в автомобиле **12 В бортовой сети нельзя подавать непосредственно на 3.3V-пины ESP32, OLED или RTC**.

Рекомендуемая архитектура питания:

```text
Автомобиль
    │
    │ 12 В
    ▼
DC/DC преобразователь
    │
    ├── 5 В → ESP32 VIN/5V*
                │
                └── 3.3 В → OLED + PCF8563
```

Конкретная схема зависит от используемой платы ESP32.

При автомобильной установке желательно учитывать:

- переполюсовку;
- скачки напряжения;
- импульсные выбросы бортовой сети;
- ток потребления ESP32;
- ток потребления OLED;
- резервное питание RTC;
- потребление ELM327 от OBD-II.

<a id="memory"></a>
## 23. Память и параметры сборки

Для сборки ESP32 Dev Module с flash **4 МБ** и ESP32 core **3.3.5**
подходит стандартная таблица разделов: приложение помещается в раздел
**1 310 720 байт**. Ранее проверенный `Minimal SPIFFS` тоже допустим, менять
уже используемую таблицу только ради этой оптимизации не требуется.
Для другой платы проверьте её объём flash и доступный раздел приложения.

Результаты сборок с одинаковыми ESP32 core 3.3.5 и библиотеками OBD/RTC/OLED:

| Показатель | Штатный BLE (Bluedroid) | NimBLE 2.5.1 с `build_opt.h` | Экономия |
|---|---:|---:|---:|
| Flash приложения | 1 688 227 Б | 1 207 823 Б | 480 404 Б (28,5%) |
| Статическая RAM | 62 324 Б | 56 992 Б | 5 332 Б (8,6%) |

Новая сборка занимает 92% стандартного раздела приложения. Статическая RAM
из отчёта компоновщика не включает динамические выделения после старта,
в том числе буферы Wi-Fi/BLE, OLED и стеки создаваемых задач. Свободный и
минимальный heap при работе с реальным адаптером на плате ещё не измерены.

BLE перенесён на [NimBLE-Arduino](https://h2zero.github.io/NimBLE-Arduino/md__migration__guide.html).
Сохранены имя устройства `NexiaBLE`, оба UUID, разрешение записи характеристики
и формат времени `YYYY-MM-DD HH:MM:SS`. Обработчик callback хранится статически;
максимальная длина значения характеристики ограничена 19 байтами.

Параметры NimBLE хранятся в [bk/build_opt.h](bk/build_opt.h), рядом
с [bk/bk.ino](bk/bk.ino). Версии зависимостей и настройки платы приведены в
[инструкции по сборке и заливке](INSTALL.md#dependencies).
